Contracts that describe the project (configuration)

These contracts are written once per project or per harness release. They decide which nodes exist for a ticket, which rules each node judges, and what instructions a unit gets. The driver reads them on every command. {{ cite('src-ticketroot') }}

How enforcement is labelled: driver = refused at runtime when wrong; partial = some fields checked; none = trusted as written. Each contract's note says exactly which checks exist.

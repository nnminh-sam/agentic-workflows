What happens inside one node

Every node runs the same cycle: plan → packet → dispatch → result → record → gate. Only the controller calls the driver, and only the unit does the work. A node with a reviewer runs the dispatch–record part twice: workers first, then the reviewer over their results. {{ cite('src-skill-loop') }}

Node record states

What the gate checks before a node is done

  1. Not already closed and ready: every required token has a done producer, otherwise G7 … not ready. {{ cite('src-gate') }}
  2. Every planned unit has an ok record in the current generation; records from older generations do not count. {{ cite('src-absent') }}
  3. The last reviewer verdict is not FAIL (nodes with a reviewer). {{ cite('src-absent') }}
  4. Every artifact file exists. This is an existence check only: content and freshness are not checked (R1). {{ cite('src-absent') }}
  5. User boundary: --actor user is required on user-boundary nodes; autoSkipPlanApproval relaxes it only on the two plan nodes. {{ cite('src-absent') }}
  6. Side effects: pin the subject digest (subject nodes), issue receipts (final-review), verify receipts (deliverable-ready), record artifact digests, and apply --reopen (triage-review). {{ cite('src-gate-effects') }}
  7. Loop cap: needs-changes at attempt ≥ {{ facts.loopCap }} raises G4 unless --actor user. {{ cite('src-gate') }}

The harness in one page

Short answer

Nodes never call each other. A node finishes by leaving files in the ticket directory and a done record in state.json. The next node may start only when every token it requires has a done producer. {{ cite('src-missing') }} {{ tag('sure') }} Everything a node receives comes through a driver-rendered packet, and everything it returns is a result file the controller records by digest. {{ cite('src-dispatch-id', 'src-record') }}

  1. Two kinds of handoff. Control moves through tokens in state.json (driver-enforced). Data moves through artifact files such as plan.md (only their existence is checked). {{ cite('src-missing', 'src-absent') }} {{ tag('sure') }}
  2. The driver is the only writer of state. It replaces state.json atomically and appends every event to decisions.jsonl. {{ cite('src-save', 'src-log') }} {{ tag('sure') }}
  3. Reruns are surgical. Invalidating a node stales only the later nodes that consume its tokens. Reopening coding keeps the {{ len(find(invalidations, 'start', 'coding').kept) }} test-case nodes. {{ cite('src-dependents', 'src-test-inval') }} {{ tag('sure') }}
  4. {{ count(contracts, 'enforced', 'none') }} contracts have no machine check at all (graph node spec, facts JSON), and three exist only as conventions. See review points. {{ tag('sure') }}
  5. Two real defects: a rerun node can pass with its old artifact, and the receipt ignores new untracked file contents. {{ cite('src-absent', 'src-subject') }} {{ tag('sure') }}

Where everything lives on disk

Everything a ticket produces lives in one directory, <ticketRoot>/<ticket>/. ticketRoot comes from the profile and resolves relative to the profile file, not the shell's working directory. {{ cite('src-ticketroot') }} {{ tag('sure') }} Source code is the one exception: it changes only in a per-ticket worktree next to each repository.

The rules files follow

  1. One writer per file. state.json and decisions.jsonl are written only by the driver. Artifacts are written only by their node's worker. Units never touch state. {{ cite('src-save', 'src-log') }} {{ tag('sure') }}
  2. Messages are immutable. Packet, rules and result names carry generation and round, so a rerun adds files and never overwrites. The unit record pins the result's sha256. {{ cite('src-dispatch-id', 'src-record') }} {{ tag('sure') }}
  3. Artifacts are mutable. A rerun overwrites plan.md in place, and nothing archives the previous generation. The approved digest stays only in artifactDigests. {{ cite('src-gate-effects') }} {{ tag('sure') }}
  4. Nothing is deleted. Invalidation changes records, not files; the stale artifact stays on disk until the rerun overwrites it, which is the root of R1. {{ cite('src-invalidate') }} {{ tag('sure') }}
  5. Review inputs are copied in. handback copies the exported review to reviews/round-N and logs its digest, so the ticket does not depend on the original file. {{ cite('src-handback') }} {{ tag('sure') }}
  6. The repository is touched only by coding (mutability source). What ships from it is pinned by the subject digest and receipt. {{ cite('src-graph-coding', 'src-subject') }} {{ tag('sure') }}
Suggested fix for mutable artifacts: on invalidate, move each stale node's artifacts to archive/g<N>/. The rerun must then recreate them, which closes R1, and you get a readable history per generation for free.
